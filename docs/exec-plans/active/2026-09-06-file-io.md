# File IO Reduction

## Objective

Keep one descriptor-based text-read implementation and the file mutation
boundary used by FileRead, FileWrite and FileEdit. Remove filesystem APIs and
process-wide coordination that have no caller in the configured runtime.

## Current Contracts

- [IO](../../design-docs/io-runtime.md) owns pinned authority, bounded reads,
  conflict detection and joined blocking work.
- [Tools](../../design-docs/tool-runtime.md) registers FileRead, FileWrite and
  FileEdit. Directory listing, walking and deletion have only test callers.
- Workspace reads already bypass pathname caches. The pathname overload keeps
  a separate reader, line index, result cache, inotify watcher and singleflight
  table; the last of these has open executor/cancellation verification debt.
- Stored capability spellings, database schemas and user rows remain intact.

## Complete Slice

1. Route trusted pathname reads and authorized handles through one bounded
   descriptor reader. Open trusted paths on the worker executor and retain
   their regular-file identity for the complete read.
2. Remove the pathname caches, watchers, singleflight state and their public
   statistics. Each read owns its resources and observes current file bytes.
3. Delete unused directory enumeration, traversal and delete APIs, associated
   authority helpers, implementations and tests. Preserve read/write authority
   and atomic-mutation regressions.
4. Keep range, UTF-8 boundary, byte-limit, error and cancellation behavior.
   Add deterministic regressions for content freshness and affected ownership
   boundaries; remove tests that only assert deleted internal machinery.
5. Update the IO contract, live debt and STATUS. Delete this plan after its
   completion criteria are met.

## Risks And Verification

- Pathname convenience reads retain their trusted-host role and symlink
  behavior; workspace dispatch continues to use its pinned authority.
- Repeated pathname reads perform IO on each call. Compare the existing IO
  benchmarks before/after and verify that the runtime's descriptor path keeps
  its bounded allocation and range behavior. This is local evidence, not
  reference-hardware compile-budget certification.
- Preserve tests for path replacement, symlink confinement, atomic writes,
  expected versions and cancellation. Prove added/rewritten behavior tests red
  against the original implementation or isolated deliberate faults.
- Run affected IO/tool/bootstrap builds and tests, the full release build and
  all test targets, `make ci`, and explicit ASan/UBSan instrumentation for
  affected lifetime paths in an isolated copy.
