| 2026-05-16 | storage-session-role | `SessionRepository` now takes and exposes a typed `core::Role` on the API boundary instead of free-form `std::string`, so callers above storage stop hand-typing role strings and rows with unknown role text surface a clear error on read. `xmake run orangutan` still reports slice 7. | `oran-core` adds `core::parse_role(std::string_view) -> std::optional<Role>`. `AppendSessionMessageRequest::role` and `SessionMessageRecord::role` switch from `std::string` to `core::Role`. The write path binds `to_string_view(role)`; the read path parses the column text back into the enum and returns a storage-kind error if it does not match a known role. `tests/core` grows to 48 cases / 276 assertions; `tests/storage` grows to 52 cases / 606 assertions (adds an enumerator-round-trip case and a bad-role-row rejection case). `bench/storage` keeps the raw-pool vs. repository A/B (raw ~796 µs vs. repository ~967 µs on this run). | [history](../histories/2026-05/20260516-1810-oran-storage-session-role.md) |
| 2026-05-16 | core-str-utf8 | Every higher layer (config values, storage payloads, CLI echo, future provider request bodies) can now reach for the same RFC-3629 UTF-8 primitives in `core::str::*` instead of re-implementing them. `xmake run orangutan` still reports slice 7. | `oran-core` adds `core::str::is_valid_utf8` (strict RFC 3629; rejects overlong encodings, lone continuations, surrogate code points U+D800..U+DFFF, code points beyond U+10FFFF), `core::str::count_code_points` (returns `std::optional<std::size_t>`; `nullopt` for invalid input), and `core::str::truncate_to_code_point` (byte budget, never splits a multi-byte sequence). Public header keeps the stdlib-only contract. `tests/core` grows to 46 cases / 266 assertions, and `bench/core` adds the strict validator walk on a 1024-byte mixed fixture (~419 ns) vs. a `std::ranges::all_of` ASCII-only short-circuit (~1.8 ns). | [history](../histories/2026-05/20260516-1740-oran-core-str-utf8.md) |
| 2026-05-16 | core-tooldef | The agent loop, provider adapters, and the future tool registry can now name the canonical tool declaration with `core::ToolDef` (name + description + opaque JSON Schema string) instead of hand-rolling per-layer shapes. `xmake run orangutan` still reports slice 7. | `oran-core` adds `ToolDef` with member-wise equality and a `ToolDef::with_no_input(name, description)` fixture helper that fills a minimal `{"type":"object","properties":{},"additionalProperties":false}` schema. | 2026-05-16 | core-message | Conversation flow between providers, the agent loop, storage, memory, and channels can now move a single canonical message type — `core::Message` (role + ordered content blocks + optional timestamp) carrying `core::Content` (`Text`/`Thinking`/`ToolUse`/`ToolResult`) — instead of every layer plumbing strings or JSON. `xmake run orangutan` still reports slice 7. | `oran-core` adds `Role`, `StopReason`, `TextContent`, `ThinkingContent`, `ToolUseContent`, `ToolResultContent`, the `Content` variant alias with `holds_*` / `text_view` helpers, and `Message` with `user_text`/`assistant_text` factories. Public headers stay nlohmann-free; tool input/output stays opaque so `oran-provider` adapters can own JSON. `tests/core` grows to 33 cases / 209 assertions, and `bench/core` adds `Content` visit-vs-get_if (~28 ns vs. ~26 ns) plus a 32-block message walk (~31 ns). | [history](../histories/2026-05/20260516-1605-oran-core-message.md) |
| 2026-05-16 | core-time | Storage rows, audit logs, and future memory records can now use a single canonical UTC `Time` type with strict ISO-8601 format/parse, instead of plumbing raw `std::chrono::system_clock::time_point` or hand-shaped timestamp strings across library boundaries. `xmake run orangutan` still reports slice 7. | `oran-core` adds `Time`, `core::time::now_utc`, `core::time::format_iso8601_utc` (deterministic `YYYY-MM-DDTHH:MM:SS.fffZ`), and `core::time::parse_iso8601_utc` (strict; rejects unknown shapes, non-UTC offsets, more than three fractional digits, lowercase separators, leading/trailing whitespace, and out-of-range fields). `tests/core` grows to 17 cases / 150 assertions, and `bench/core` adds explicit-format vs. chrono-format scenarios plus a parse cost scenario (~339ns vs. ~174ns format, ~46ns parse). | [history](../histories/2026-05/20260516-1450-oran-core-time.md) |
