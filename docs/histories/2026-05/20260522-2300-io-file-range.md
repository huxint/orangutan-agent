- Key actions:

    `ByteSpan`) and `io::ReadTextResult { text, fingerprint,
    start_line, end_line, returned_bytes, truncated }` in a new public
    header `<oran/io/range.hpp>` and re-exported them via
    `<oran/io.hpp>`.
  - Extended `ReadTextOptions` with `std::optional<FileRange> range`.
  - Added the new `io::read_text_file_ranged(executor, path, options)`
    public coroutine returning `Result<ReadTextResult>`. Validates the
    range, captures a pre-read fingerprint, performs a streaming read
    that honors the range and `max_bytes`, captures a post-read
    fingerprint, and either retries once (small whole-file reads on
    fingerprint drift) or surfaces `Error::conflict` (large or ranged
    reads on drift).
  - Reused a single `read_text_file_blocking` impl for both the rich
    return path and the legacy `Result<std::string>` wrapper; the
    legacy `io::read_text_file` now calls the ranged path and
    promotes `truncated=true` to `Error::invalid_argument` so its
    historical "errors when file > max_bytes" semantics survive.
  - Wrote `align_to_utf8_boundaries(buffer)` to drop leading
    continuation bytes AND trim trailing partial multi-byte sequences;
    byte ranges always run through it so the returned text stays valid
    UTF-8 even when `offset_bytes` / `length_bytes` land mid-codepoint.
    The line-range and whole-file paths run through it only when
    truncation fires.
  - Added 13 new Catch2 cases covering whole-file metadata, trailing
    partial line, `max_bytes` truncation, line range, line range
    capped by `max_bytes`, line range past EOF, byte range, byte
    range past EOF, byte range splitting a UTF-8 code point, empty
    range rejection, both-set range rejection, zero-field rejection,
    and a best-effort mid-read race test on a 96 KiB seed that
    tolerates both "conflict" and "completed before race" outcomes.
  - New `bench/io/scenarios/read_range.cpp` pins the 10 MiB whole-file
    read (~11.5 ms) vs. 80-line range (~18.9 µs) — about 610× faster
    for the ranged path on this hardware.
  - Bumped the version banner to slice 43.

### Design Intent

Spec 0011 v1 names a `ReadTextResult` shape that wraps text with
fingerprint metadata and span / truncation flags so every caller of
the file-view surface speaks the same vocabulary. Landing the data
type, the range validation, and the mid-read race detection in a
single slice keeps the change scoped to `oran-io` — the future
`file.read` v2 schema, the version-token shape, and the
`if_version` short-circuit are tool-layer concerns that slot on top of
this contract.

The legacy `read_text_file` returning `Result<std::string>` stays
because (1) `oran-tool/file_read.cpp` and `oran-tool/file_edit.cpp`
both call it and a migration would balloon this slice past the 600
line / 6 file guideline, and (2) the spec explicitly carves a
"thin wrapper for non-tool callers". Promoting `truncated=true` to
`Error::invalid_argument` preserves the historical "file too large"
error contract while keeping the rich path additive.

Mid-read race detection is wired on the legacy path too so the agent
loop never silently observes a torn read; the ~2 × 1.3 µs fingerprint
overhead is small compared to the ~3.7 µs raw read of a small file
and noise compared to the ~11.5 ms 10 MiB read.

UTF-8 boundary alignment uses an inline helper rather than the
existing `core::str::truncate_to_code_point` because the helper's
early-return contract (`text.size() <= max_bytes` returns unchanged)
defeats the trailing-trim use case, and because byte ranges need a
*both-end* aligner (leading continuation bytes from a mid-codepoint
seek must also be dropped). If a second consumer appears we'll
promote `align_to_utf8_boundaries` into `core::str`.

The mid-read race test uses `std::thread` rather than a
fault-injecting filesystem mock; production code never gets that
include (rule C2 only bans `<thread>` outside tests/bench). The test
asserts the *invariant* — no false-`value` on conflict — rather than
deterministically firing the race, which would need infrastructure we
do not yet have.
